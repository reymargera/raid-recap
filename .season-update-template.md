# Season Update Template

This document outlines the step-by-step process for updating the Raid Recap site for a new WoW season.

## Prerequisites: Information Gathering

Before starting the update, gather the following information:

### Basic Season Information
- [ ] Season Name: `_______________________`
- [ ] Season Number: `_______________________`
- [ ] Season Start Date/Time (UTC): `_______________________`
- [ ] Raid Name: `_______________________`

### Raid Encounters
Create a list of all bosses with their encounter IDs and names:

```
Boss 1: [ID: ____] Name: _______________
Boss 2: [ID: ____] Name: _______________
Boss 3: [ID: ____] Name: _______________
...
```

**How to find encounter IDs:**
- Check WarcraftLogs URLs (e.g., `warcraft-logs.com/zone/reports?zone=38` where 38 is the zone)
- Use WarcraftLogs GraphQL API explorer
- Reference previous season updates in git history

### Mechanics to Track
For each mechanic you want to track, gather:

```
Mechanic Name: _______________
Boss: _______________
Ability ID(s): _______________
Wowhead Link: https://www.wowhead.com/spell=______
Type: [DPS Loss / Debuff / Buff / Death / Damage Taken]
Stat Key Name: _______________ (camelCase, e.g., 'timesStoodInFire')
Description: _______________
Award Name: _______________ (optional)
Award Description: _______________ (optional)
```

**How to find ability IDs:**
- From Wowhead URL: `https://www.wowhead.com/spell=469795` → ID is `469795`
- From WarcraftLogs: Check the ability in the events/damage tables
- From in-game combat log

## Step 3: Update Seasonal Stats Keys

**File:** `src/warcraft-logs/model/player-stats.ts`

### Task
1. Create new seasonal stat keys array (e.g., `TWWSeason3StatKeys`)
2. Update `SeasonalStatKeys` to reference the new season
3. Ensure stat keys match the mechanics you want to track

### Template
```typescript
export const TWWSeason[N]StatKeys = [
    '[statKey1]',  // e.g., 'timesStoodInTrash'
    '[statKey2]',  // e.g., 'timesRolledOver'
    '[statKey3]',  // e.g., 'highRollerUptime'
    // ... add all seasonal mechanics
] as const;

export const SeasonalStatKeys = [...TWWSeason[N]StatKeys];
```

### Stat Key Naming Conventions
- Use camelCase
- Be descriptive but concise
- Common patterns:
  - `times[Action]`: Count of occurrences (e.g., `timesStoodInFire`)
  - `[mechanic]Uptime`: Duration tracked in milliseconds (e.g., `debuffUptime`)
  - `[mechanic]Applications`: Times debuff was applied (e.g., `staticDischargeApplications`)
  - `[mechanic]Casts`: Times ability was cast (e.g., `blazeOfGloryCasts`)

### Example
```typescript
export const TWWSeason3StatKeys = [

    'timesRolledOver',
    'timesRollingOver',
    'timesScrewed',

    'timesCrushed',
    'coinsPushed',

    'coilsDestroyed',

export const SeasonalStatKeys = [...TWWSeason3StatKeys];
```

## Step 6: Update GraphQL Queries

**File:** `src/warcraft-logs/queries/GetReport.ts`

### Task
1. Create GraphQL fragments for each mechanic
2. Add fragments to main query
3. Extract data in `log-puller.ts`

### Understanding WarcraftLogs Data Types

**Common Query Types:**
- `table(dataType: DamageTaken)`: Damage taken from abilities
- `table(dataType: Debuffs)`: Debuff applications/removals
- `table(dataType: Buffs)`: Buff applications/removals
- `table(dataType: Casts)`: Ability casts
- `table(dataType: Deaths)`: Death events
- `events(dataType: Debuffs)`: Raw debuff events with filters

**Common Filters:**
- `abilityID: [ID]`: Filter by specific ability
- `filterExpression: "..."`: Complex filtering using WCL query language
- `fightIDs: $bossFightIds`: Limit to specific fights

### Fragment Template

```typescript
export const [MechanicName]Fragment = gql`
    fragment [MechanicName]Fragment on Report {
        [queryName]: table(
            fightIDs: $bossFightIds
            dataType: [DataType]
            abilityID: [ABILITY_ID]  // optional
            filterExpression: "[filter]"  // optional
        )
    }
`;
```

### Common Patterns


## Step 7: Extract Data from Reports

**File:** `src/app/teams/[id]/log-puller.ts`

### Task
Update `extractPlayerStatsFromFightReport()` to extract new mechanic data from GraphQL results.

### Understanding the Data Structure

WarcraftLogs returns data in this structure:
```typescript
{
    data: {
        entries: [
            {
                guid: [PLAYER_ID],
                name: "[Player Name]",
                total: [NUMBER],        // for damage/healing
                totalUptime: [MS],      // for debuff/buff duration
                uses: [NUMBER],         // for casts
                // other fields...
            }
        ]
    }
}
```

### Template for Data Extraction

```typescript
// In extractPlayerStatsFromFightReport function

const [statKey] = report?.[graphqlFieldName]?.data.entries
    .reduce((map: PlayerAccumulator, entry: any) => {
        map[entry.guid] = entry.[fieldToExtract];  // e.g., entry.total, entry.totalUptime
        return map;
    }, {}) ?? {};

// Then return it at the bottom:
return {
    // ... existing stats
    [statKey],
};
```

### Common Extraction Patterns

#### Pattern 1: Count Applications (from debuff table)
```typescript
const timesScrewed = report?.screwedApplications?.data.entries
    .reduce((map: PlayerAccumulator, entry: any) => {
        map[entry.guid] = entry.total || 0;
        return map;
    }, {}) ?? {};
```

#### Pattern 2: Track Uptime (in milliseconds)
```typescript
const highRollerUptime = report?.highRollerUptime?.data.entries
    .reduce((map: PlayerAccumulator, entry: any) => {
        map[entry.guid] = entry.totalUptime || 0;
        return map;
    }, {}) ?? {};
```

#### Pattern 3: Track Damage Taken
```typescript
const fireDamage = report?.fireDamage?.data.entries
    .reduce((map: PlayerAccumulator, entry: any) => {
        map[entry.guid] = entry.total || 0;
        return map;
    }, {}) ?? {};
```

#### Pattern 4: Track Cast Count
```typescript
const bombsCast = report?.bombsCast?.data.entries
    .reduce((map: PlayerAccumulator, entry: any) => {
        map[entry.guid] = entry.uses || 0;
        return map;
    }, {}) ?? {};
```

#### Pattern 5: Count by Name (for mechanics that target by name, not ID)
```typescript
const mechanicByName = report?.mechanic?.data.entries
    .reduce((map: PlayerAccumulator, entry: any) => {
        map[entry.name] = entry.total || 0;
        return map;
    }, {}) ?? {};
```

### Return Statement
Add all extracted stats to the return object:

```typescript
return {
    damage,
    healing,
    casts,
    dispels,
    interrupts,
    damageTaken,
    deaths,

    [statKey2],
```

### Full Example
```typescript
function extractPlayerStatsFromFightReport(report: MaybeReportType) {
    // ... existing extraction code ...

    // Seasonal stat extraction
    const timesStoodInTrash = report?.garbagePileDamage?.data.entries
        .reduce((map: PlayerAccumulator, entry: any) => {
            map[entry.guid] = entry.total || 0;
            return map;
        }, {}) ?? {};

    const timesScrewed = report?.screwedApplications?.data.entries
        .reduce((map: PlayerAccumulator, entry: any) => {
            map[entry.guid] = entry.total || 0;

    const highRollerUptime = report?.highRollerUptime?.data.entries
        .reduce((map: PlayerAccumulator, entry: any) => {
            map[entry.guid] = entry.totalUptime || 0;
            return map;
        }, {}) ?? {};

    return {
        damage,
        healing,
        casts,
        dispels,
        interrupts,
        damageTaken,
        deaths,
        powerInfusions,
        mechanicsTaken,
        friendlyFireDone,
        friendlyFireTakenByName,

        // Seasonal stats
        timesStoodInTrash,
        timesScrewed,
        highRollerUptime,
    };
}
```

## Common Issues and Solutions

### Issue: Ability ID not tracking
**Solution:**
- Verify ability ID is correct in WarcraftLogs
- Check if ability has multiple IDs (different ranks/difficulties)
- Ensure GraphQL query is properly formatted
- Test the query in WarcraftLogs GraphQL explorer

### Issue: Stats showing as 0 or undefined
**Solution:**
- Check data extraction mapping (guid vs name)
- Verify field names match (total vs totalUptime vs uses)
- Add null coalescing (`?? {}`) to prevent undefined errors
- Check if fights are being categorized correctly (boss vs trash)

### Issue: TypeScript errors
**Solution:**
- Regenerate GraphQL types: `npm run generate` or equivalent
- Check that new stat keys are added to `SeasonalStatKeys`
- Ensure all seasonal stats are initialized in `generateBlankStats()`

### Issue: Awards not displaying
**Solution:**
- Check `SeasonalAwards` array includes new awards
- Verify `CurrentAwards` array is exported and used
- Check background image paths are correct
- Ensure stat key names match between awards and player-stats
